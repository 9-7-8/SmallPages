PDF OCR

A PDF of scans in, the same PDF out with the words in it. Every page is drawn, read, and given an invisible layer of text sitting exactly over what it says — so the document looks identical and can be searched, selected and copied. Built for long ones: a document of several hundred pages is read a page at a time and never held in memory all at once.

The pages are not touched. The document you get back is the one you put in — the same pages, the same pictures, the same size, nothing re-encoded or flattened — with one extra stream of text added to each page it read, drawn in the invisible render mode the format has for exactly this. Open it and it looks the same; press ctrl-F and it is a different document. Pages that already had text keep it and are left alone, so running this over a document twice does not give it two layers.

Long documents are the point. A page is drawn, read and thrown away before the next one starts, so what the tab holds is the file itself and a few words per page rather than hundreds of rendered images: three hundred pages costs time, not memory. The bar says where it has got to and Stop stops it between pages — what has been read by then is kept, and reading again carries on with the pages that are still waiting. The map of pages says which is which, and a range box means a long document can be done twenty pages at a sitting.

Half-typed documents only get read where they need it. Before anything is drawn, each page is asked whether it already has real text in it — a page exported from a word processor does, a photograph of a page does not. The ones that do are left exactly as they are and their own text is what goes into the text file. That is usually the difference between a few minutes and an hour, because most mixed documents are mostly typed.

The text sits where the words are. Each line is placed over the box the reader found it in, at that box's height, squeezed to that box's width — which is what makes selecting a paragraph in the finished document select the paragraph rather than a rectangle somewhere near it. Pages turned by the document's own rotation are handled: the text is written into the page's own coordinates and comes out the right way up whichever way the page is displayed. Correcting a page in the box above rewrites its lines in order; adding lines past the end stacks them under the last box.

The reading is done here, by Tesseract. Tesseract.js with the English model, about 7 MB of engine and training data in vendor/tesseract/, loaded the first time you press read and then held for the rest of the session. The drawing is pdf.js and the writing is pdf-lib, both in this repository too. Nothing is fetched and nothing is sent: the document never leaves the tab. The one thing it needs is to be served over HTTP rather than opened off the filesystem, because a browser will not start a worker from a file:// folder.

It is a reading, not a transcript. Tesseract is good and it is not perfect: it mangles small print, unusual faces, tables and anything at an angle, and it cannot read handwriting at all. The invisible layer makes a scan findable; it does not make it authoritative. The text is written in Helvetica with anything outside the format's Latin encoding turned into a question mark, which only ever shows up in a search.
