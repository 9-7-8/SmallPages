House Style

A monochromatic glow on true OLED black. One typeface, one accent, square corners, and hairlines instead of shadows. This page links theme.css like every other page here and declares no colour of its own, so the two knobs below move the real thing and the swatches read back what the browser actually resolved.

The two knobs

Every colour in the repo comes out of --sat and --h. Nothing else is a colour decision. --sat is the master: at 0 hue drops out entirely and the accent is white, which is what ships. Raise it and --h starts to show.

--sat — 0 is the white glow, 1 is full colour
--h — does nothing while --sat is 0

Saturation is scaled by --sat throughout, and the accents climb toward white as colour drains out, so they stay accents rather than collapsing into mid-grey. That is why there are four lightness ramps in the theme and not four fixed lightnesses.

Colour

Read back out of the page with getComputedStyle, so these are the values in force right now — the same trick anything → image uses to make canvas output match the page it was drawn on.

Rules that hold whatever the knobs say

  • Black is black. --bg is #000000, so OLED pixels switch off. Depth comes from hairlines and glow, never from lighter greys.
  • Glow is reserved. --neon and the three shadow tokens mark what is live, focused or clickable. A static label never glows.
  • There is no second hue. Failure is signalled by intensity and a bar on the left, not by red; nothing here is green for success.
  • Three deliberate exceptions. The transparency checker is a neutral grey outside the palette, because it has to read as "there is nothing here" rather than as part of the design. A page that draws its own pixels pulls resolved colours out rather than hard-coding them. And hex clock paints its own background, because the background is the point — its chrome steps off the ink ramp too, since that ramp is mixed for a page that is always pure black.

Type

One family doing every job, differentiated by weight and tracking. --sans is Lexend Deca, falling back to Helvetica. --mono is a system stack — nothing downloaded — used only for text that is literally a command, a path, a token name or a column of figures. Those get font-variant-numeric: tabular-nums so they stop jittering as they update; where the face has no tabular figures, as Lexend Deca does not, a column that must hold still gets fixed boxes per character instead.

Shape

  • Square corners. border-radius: 0 on everything. The one radius in the system is 2px on the focus ring, so it does not read as a hard corner.
  • Hairlines, not shadows. --line and --line-soft separate things; box shadows exist only as glow.
  • Three surfaces. --bg for the page, --raised for a card, --sunken for anything you type into.
  • One reading column. Pages cap at 760–900px and running text at 56–68ch. Below 620px rows stack and action buttons go full width.
  • A grid once a list gets long. Up to about a dozen entries a list reads as a set of things you pick from. Past that it reads as a column of text you have to scan, and it becomes a grid of tiles instead — auto-fill on a minimum tile width, so it finds its own column count and comes down to one on a phone without a breakpoint deciding where. The index crossed that line at twenty-three.
  • Hairlines on the tiles, not behind them. A grid of hairlines is tempting to build as a 1px gap over a coloured ground. Do not: the last row is nearly always short, and the empty slot shows the ground through as a block of grey with nothing in it. Put the lines on the tiles and the gap simply ends where the tiles do.

Icons

The index gives every tool an icon. They are drawn to the same geometry as everything else here, which is most of what makes a set of twenty-three look like one set:

  • A 24-unit box, drawn at 26px, with nothing crossing the edge.
  • Strokes, not fills. stroke: currentColor at 1.25, and fill: none unless a shape is meant to read as solid — those get fill="currentColor" at about 0.4 opacity, so a filled cell is a shade rather than a block.
  • Square caps, mitred joins. stroke-linecap: square and stroke-linejoin: miter, because nothing else in the repo has a rounded corner either.
  • Colour from the theme, never their own. --neon-deep at rest: present, but not claiming to be the live thing on the page. On hover and on focus they go to --neon with a drop shadow, so the glow still means what it means everywhere else.
  • One <symbol> each, referenced. The page holds one copy of each drawing rather than one per tile.
  • About its own tool. Not a generic glyph: the texture strip for .mcmeta, bezier nodes on a curve for the tracer, two overlapping circles for cross-mixing, the pivot tick for the speed reader, the two sliders for this page.

Draw it, then look at it. Two of the index's icons were wrong the first time and only reading as wrong on screen: the colour picker came out looking like a pencil until its bulb and barrel were turned forty-five degrees, and bingo and the word puzzles were the same grid twice, sitting next to each other, until bingo became three round daubs on a diagonal. At 26px the difference between two icons has to survive being glanced at.

These six are a copy, and the only one on the page. Everything else here reads the real thing back out of theme.css, but an icon set cannot be shared that way: an external <use href="icons.svg#id"> does not resolve from a file:// page, and every page here has to work when it is handed over on its own. The set lives in index.html; these are six of it, at the size they are used, to show the weight.

Motion

Transitions run at 0.15s ease on colour, border and shadow, and on nothing else. A page gets at most one thing that moves on its own, and only while something is genuinely happening: the microphone pulse while recording, the sweep on a progress bar that cannot report a percentage, the caret on a line still being written. All of it is switched off under prefers-reduced-motion, in the theme and again in any page that adds a keyframe of its own.

Words

Copy is part of the design. British English, plainly, the way a knowledgeable person would say it — short sentences, active voice, specific over clever. Notes open with a bolded phrase and then explain themselves. Nothing apologises and nothing oversells: a page says what it does, and then says what it is bad at.

Casing

Names of things are Title Case. Everything else is Sentence case, capitalised on the first word only.

WhereHow
Title CasePage titles, h1, and the index entry — Audio → Text, Bingo Cards, PNG → Swirl GIF.
Sentence caseSection headings, labels, buttons, options, tooltips, aria-labels, status lines, and the one-line description under each index entry.
As writtenAcronyms are acronyms — CMYK, JSON, SVG, OKLCH. Brand names take their own casing — GitHub, CurseForge, Pantone.
Left aloneFile extensions (.txt, .srt), CSS and colour-space literals (sRGB, hsl(…)), shell names, domains, units (dB), usernames, and the example content in a placeholder.

This covers the text people read, wherever it is written: an option built in JavaScript is as client-facing as one in the markup. It stops at the text — identifiers, keys, class names, data attributes and comments keep whatever casing the code wants. Mid-sentence emphasis stays lowercase, because that is what English does; the exception is a <b> naming a control rather than a word in the sentence.

A page's skeleton

Every page is one standalone HTML file that runs entirely in the tab. Nothing is uploaded, and any page here can be handed to someone as a single file.

<link rel="stylesheet" href="theme.css">
<style> /* Layout and sizing only. Colour, type and component
           styling live in theme.css. */ </style>

<main>
  <a class="home" href="index.html">← index</a>
  <h1>Page Name</h1>
  <p class="lede">What it does, in two or three sentences.</p>

  <div class="card"> … the input …    </div>
  <div class="card"> … the controls … </div>
  <div class="card"> … the result …   </div>

  <p class="note"><strong>It runs here.</strong> How it works, and
  what it will not do.</p>
</main>

The back link sits directly above the title on every page but the index. Cards run down the page in the order the job happens — put something in, set it up, read it back. The notes at the foot are where the page is honest about its limits: what gets fetched, what it is bad at, and what it needs a real machine for. Then add a row to the <nav> list in index.html and to the table in the README.

Written from the theme, not about it. The knobs above set --sat and --h on :root, the swatches read the resolved values back, and the components in the gallery are the real classes. If any of it looks wrong, the theme changed and this page is already telling you so.

One look, on purpose. There is no light mode anywhere in this repo, here included. A style guide for an OLED-black palette shown on white would be describing something else.
