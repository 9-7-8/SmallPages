Make Cassette Image

Put a picture in the window of a VHS cassette, write the title on the tape stuck across the front, and take away a square cover. The shell and the label are photographs laid over your image rather than filters applied to it, and the whole thing happens on a canvas in this tab.

The window was in the wrong place. The script this came from hard-coded the window as 1358×825 but worked out where to put it by centring it on the canvas, which lands it at 1155 pixels down when the hole in the shell actually starts at 1222. Every cover it made was therefore 67 pixels out: the top of the picture hidden behind the shell, and a strip of bare backing showing along the bottom of the window. The folder even carried a window.png mask giving the true position — the script opened it and then never used it. Here the measured position is the one used.

The artwork lives in this repo. The shell and the label are in vendor/cassette/, and the display faces are in vendor/fonts/ alongside the ones Make CD Image draws with, since the two tools were always reaching for the same drawer. They come in through vendor/cassette/art.js as data URIs, which looks like a strange way to ship two PNGs until you open this page straight off the filesystem: a browser counts a sibling file:// image as cross-origin, draws it quite happily, and then marks the canvas tainted, so every save throws and the buttons appear to do nothing. The full-size PNGs are in the same folder and the page falls back to them if the bundle goes missing.

The title is fitted, not set. As in the original, the size is found by binary search — the largest that fits the label with a margin — so a long title shrinks to fit rather than running off the tape. The difference is that it is measured on the ink rather than on the font's ascender box, so a title with descenders in it sits centred on the tape instead of riding low. The outline is a stroke rather than four offset copies of the text, and it has a width you can set: the original asked for one pixel on a 3135-pixel canvas and then scaled the result down to 750, which is a way of asking for nothing.

The picture is cropped, not squashed. It is scaled to cover the window at whatever zoom you set, and across and down move it inside that window, so the aspect ratio it arrived with is the aspect ratio it keeps. Brightness and contrast are the canvas filter, so they apply to the picture and not to the shell over it.

It runs here. Nothing is uploaded; the canvas is read back into a file by your own browser. The original wrote one file per picture per face, every combination, into an output folder; this is the same drawing with the choice made by looking at it.
