The script this came from could not run. Its padding step ended with return Image.new(...).paste(image, ...), and paste works in place and returns nothing — so every padded image came back as None and the next line fell over. The row branch also still asked for Image.ANTIALIAS, which Pillow removed in version 10. Neither is the interesting one, though.

The sizing was wrong as well. It worked out the cell by taking each picture's width and multiplying it by the number of columns, then kept the largest — so one cell came out as wide as the whole sheet was meant to be, and the sheet itself came out as that again times the column count. Three pictures across at 1000 pixels each would have asked for a canvas 9000 pixels wide with each picture filling a third of it. Here a cell is a square big enough for the largest picture you gave it, and the sheet is that cell times the grid, which is what the README described all along.

Nothing is upscaled. Left on its own the cell is sized from the longest edge in the set, so the biggest picture is the one that fits exactly and everything else is scaled down to meet it. Set the cell yourself and a small picture will still not be blown up past its own size — it is centred in the cell instead, which is the honest thing to do with a picture that has no more detail to give.

A browser will not paint a canvas of any size. Past roughly 16,000 pixels on a side, or about 270 million pixels in total, it hands back a blank one with no error at all. The cell is capped so the sheet stays inside that, and the line above the preview says what you are actually getting and whether it had to come down.

It runs here. Nothing is uploaded. A .png keeps the padding transparent, which is the point of padding it rather than filling it. The .jpg flattens onto white first, because a JPEG has no transparency and would otherwise come back with the gaps in black.
