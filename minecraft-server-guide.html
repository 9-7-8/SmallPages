First join

Four things to get in place before Minecraft will even let you knock: Tailscale, LocalSend, the right NeoForge build, and the pack itself. Follow these in order — each one depends on the one above it.

NeoForge must be 26.1.2.109 or above. This is the single most common reason a client won't start. Anything older is refused — and the error blames a mod rather than the version, so it is easy to misread.

These steps assume the official Minecraft Launcher. A third-party launcher — HMCL, Prism, MultiMC, the CurseForge app — works too, but the menus differ and two things bite: HMCL will not open at all on a plain JDK, and launchers that copy or share instances can leave you on the wrong Minecraft. Both are on the Troubleshooting tab.

Getting on the network

The server isn't on the open internet. It lives on a private Tailscale network, so there is nothing to port-forward and nothing for strangers to find — but you have to be let in first.

Isabel shares one machine with you: the server. You are not joining her network, and you cannot see anything else on it — which is why this is now four steps rather than the six it used to be.

  1. Make a Tailscale account first.

    Sign up at tailscale.com before you install anything. Any account will do — Google, Microsoft, GitHub, a plain email address. It does not have to match anything you told Isabel.

    You are making your own free account here, not joining hers, and it stays that way.

  2. Then download and install Tailscale.

    Get it from tailscale.com/download and sign in with the account you just made.

  3. Open Isabel's share link and accept it.

    She sends you a link. Open it while signed in to Tailscale, and accept. That hands you the server and nothing else.

    There is no network to switch to, nothing to log out of, and nothing to pick from a list. If anyone talks you through those steps, they are describing the old way.

  4. Check Tailscale says Connected.

    Leave it running whenever you play. If Tailscale is off, the server simply won't appear in your list.

    The test: open the downloads page. It lives on the shared machine and nowhere else, so if that page loads, everything above worked. If it doesn't, open the share link again and check that it really says accepted.

  5. Install LocalSend — optional, as a fallback.

    You will normally download the pack from the link in the next step. LocalSend is worth having anyway for when that is not an option: it is free, open source, on every platform, and sends a file straight from one machine to another with no upload in between.

  6. Download the pack.

    Once Tailscale says Connected, open the download page. It only exists on the tailnet, so if it loads, your Tailscale is working — which makes it a useful test on its own.

    Take the full pack the first time. Later, when the server changes, that same page carries a small update pack instead — a few MB rather than a few hundred, and the page always lists the current one.

    If the page won't load, Tailscale isn't connected yet. Failing that, ask Isabel to send it over LocalSend instead.

    Don't unzip it yet.

Installing the pack

  1. Launch plain Minecraft 26.1.2 once.

    In the Minecraft Launcher, play version 26.1.2 with no mods, let it reach the title screen, then quit. This makes the launcher download the files NeoForge is about to build on top of. Skipping it is the most common reason the next step fails.

  2. Install NeoForge 26.1.2.109 or newer — never older.

    26.1.2.109 is a hard minimum. Mods in this pack refuse to load below it. .106 will not work, and neither will anything else under .109.

    On that page pick 26.1.2.109 (or a higher 26.1.2.x if one exists by the time you read this) and download the Installer. Run it — double-click, or java -jar neoforge-26.1.2.109-installer.jar — choose Install client, leave the path pointing at your .minecraft folder, and press OK.

    If you are below the minimum the game stops during loading and names a mod, not a NeoForge version — something like "requires neoforge 26.1.2.109 or above". That message means this step, nothing else.

  3. Make a separate installation with its own folder.

    This keeps 370 mods away from your existing worlds. In the launcher: Installations → New installation, set Version to neoforge-26.1.2.109, and set Game directory to a new empty folder — something like C:\Minecraft\isabel-server. Save it.

    If you'd rather not bother, you can skip this and use your normal .minecraft — but move your existing mods folder somewhere safe first, because the pack has to be the only thing in there.

  4. Copy all four folders in.

    Open the zip and copy mods, config, kubejs and resourcepacks into the game directory you just set. If you're asked whether to merge or replace, choose replace.

    All four matter. config and kubejs are not optional extras — several mods build their item lists from those files, so a client without them knows about different items than the server does and gets refused on connect.

    You want <game directory>/mods/ full of jars — not mods/mods/, which is the classic mistake. There should be 370 files in there when you're done.

    If you skipped the separate-installation step, the default game directory is:

    • Windows — %APPDATA%\.minecraft
    • macOS — ~/Library/Application Support/minecraft
    • Linux — ~/.minecraft
  5. Give Java more memory.

    Still in Installations, edit your new installation, open More options, and find the JVM arguments box. Change -Xmx2G to -Xmx8G (or -Xmx6G if your machine has 8 GB of RAM total). Leave the rest of the line alone. The default 2 GB will not load this pack.

  6. Launch it, and expect to wait.

    First startup takes several minutes and looks frozen more than once. That's normal for 370 mods. It's much quicker every time after.

  7. Add the server and connect.

    Multiplayer → Add Server, then the address Isabel gives you. Check Tailscale says Connected first. The first join builds a lot of caches and can sit on "Loading terrain" for a while.

  8. Open the quest book.

    There's an FTB Quests book covering the tech and progression mods. It's the best map of the pack that exists, and it hands out starting gear. Find Open Quests in Controls if it isn't bound.

Server address: ask Isabel — it isn't written down here on purpose.

Something went wrong? Every error worth knowing about — refused connections, crashes on startup, the mods that misbehave — is on the Troubleshooting tab, each one with the exact message you'll see and what to do about it.

Your first hour

Normal survival rules apply. Punch wood, make tools, don't dig straight down. The differences worth knowing on night one:

  • Death is survivable. Epitaphs places a grave where you died, holding your things. Walk back and collect it.
  • Sleeping is a group activity. You don't need everyone in bed to skip the night, but you do need enough people. Get in bed and wait a moment.
  • Check recipes in-game. JEI is the recipe viewer: hover any item and press R for how to make it, or U for what it's used for. With 370 mods this is the most useful key on your keyboard.
  • Don't build anything permanent yet. Claim first — see the next tab. Unclaimed land is not protected.

Claiming land

Land protection is handled by FTB Chunks, but you drive it from the JourneyMap fullscreen map. You claim whole chunks — the 16×16 columns Minecraft is built from — and everything inside becomes yours.

How to claim

You claim from the JourneyMap fullscreen map, not from a separate FTB Chunks screen. JourneyMap is the pack's map mod, and FTB Chunks hangs its claiming off it.

  1. Open the JourneyMap fullscreen map.

    The key is M. If that does nothing, look for Open JourneyMap Fullscreen Map in Controls — this pack ships KeybindsPurger, which strips keybinds, so don't assume the default survived. Clicking the minimap works too.

  2. Press the claim button in the UPPER LEFT of that screen.

    That is the one that turns the map into the chunk grid. It is easy to miss among the other map buttons — it is in the top-left cluster, not with the map-type or waypoint controls.

  3. Drag across the grid.

    The controls are below. You stay inside JourneyMap the whole time; the grid is an overlay on the map you were already looking at.

With the grid open:

  • Left-dragClaim the chunks you drag across
  • Right-dragUnclaim them again
  • Shift + Left-dragForce-load — keeps the chunk running while you're away
  • Shift + Right-dragStop force-loading
  • Hold TabHide the grid to see the map underneath

Dragging has three shapes, switched in FTB Chunks' client settings under Chunk claiming mode: Rectangular (the default), Circular, and Freehand. Rectangular is what you want almost always; freehand is for tracing an awkward border.

Claiming protects land. Force-loading is different and more precious: it keeps your machines ticking when nobody is nearby. Spend those on farms and power generation, not on your house.

Your limits

These are per player, not per team. When you join a team the members' allowances pool, so two people together can claim 1000 chunks and force-load 50. Claiming works in every dimension — this server sets no dimension restrictions on it.

Do not claim the spawn village. Nothing in FTB Chunks stops you, but spawn is separately protected and is meant to stay common ground — claiming it would only lock your friends out of the shop and the stables. Build your base somewhere else and claim that.

Teaming up

If you're building with someone, make a team rather than claiming separately. A team shares its claims, its allowances and its permissions — so you can both edit the base, and neither of you is locked out of the other's chests.

Team commands live under /team, from FTB Teams. Create one, invite the other person, they accept. Your claims merge into a shared pool from then on.

Claim before you build. Claiming after the fact works fine, but anything left unclaimed overnight is fair game for mobs and explosions even if your friends behave.

Money & shops

Money is a bank balance in dollars now, not something you carry - though you can withdraw it as cash if you like. Shops are ordinary chests with a sign on them. There is still no buying from across the map: if you want to trade, you travel.

Open your own shop

  1. Put a chest down and fill it with what you're selling.

    Any chest. Whatever is inside is your stock, so put in as much as you're happy to part with.

  2. Place the sign on it yourself.

    On the front of the chest, or on any block touching it. It has to be you who places it - that is the moment the shop records you as its owner.

  3. Hold the item, look at the sign, and run /shop.

    The command writes every line for you, including modded ids far too long to type into a sign editor. The shop works the moment it finishes.

  4. Closing it down.

    Break the sign. The chest and everything in it stays yours.

You areRun thisThe sign ends up saying
selling an item at $5/shop sell 5[buy]
buying an item at $5/shop buy 5[sell]

The command is named after what you are doing; the sign is named after what your visitor does. So /shop sell 5 correctly writes [buy] on the sign. That is not a bug - do not "fix" it by running the other one, because a [sell] shop pays money out.

If you would rather write the sign by hand

You do not need to - /shop exists precisely so nobody has to - but the four lines are:

LineWhat goes on itExample
1[buy] or [sell][buy]
2the price12
3the itemdiamond
4the rest of the item id, if it was too long for line 3 - otherwise empty 

[buy] and [sell] are named for what your visitor does, not what you do. [buy] is the one you want almost always: you stock the chest, people buy out of it, and the money lands in your account. [sell] is the opposite - it pays people to hand items in, so it needs money in your account and free space in the chest, and it stops the moment either runs out.

Writing the item name. Ordinary items can be written plainly, like diamond or oak_log. Anything from a mod needs its full id - press F3 + H to turn on advanced tooltips and the id appears in grey under the item's name.

Buying from someone else

Right-click their sign. It tells you what's for sale and the price, and one right-click buys one item - there is no stack-at-a-time shortcut, so click away.

Prices are set by whoever owns the shop, not by the server. Shop around - literally.

Selling in bulk

The price on a sign is per item, and one click moves one item. There is no way to write "64 for $10" on a sign, and no modifier key that buys a stack — so a bulk deal has to be priced per item, and the buyer clicks.

For something as cheap as cobblestone that is hopeless: $10 a stack works out at 0.16 each (prices go to two decimals, and 0.01 is the floor), so sixty-four clicks for $10.24.

Trade the compressed block instead. AllTheCompressed turns a 3×3 of almost anything into one block, so one click can move a lot:

ItemPlain cobble it holdsPrice at $10 a stack
Cobblestone 1x91.41
Cobblestone 2x8112.66
Cobblestone 3x729113.91

Each tier is nine of the one below, so the numbers climb fast — and compressed blocks still stack to 64 in the chest, so one chest holds an absurd amount of stone.

Nobody can rob your shop. Only you can open the chest or break the sign, even if it is standing in the open. Claiming the chunk on top of that does no harm.

Cash, ATMs and paying people

/money shows your balance and /pay <player> <amount> sends money to someone. Neither needs you to be anywhere in particular.

The balance is the real thing, but it does not have to stay abstract: an ATM turns it into notes and coins and back again, a Banker Table does the same job, and wallets keep the cash tidy in your inventory. Cash in your pockets is not your balance - deposit it first if you want to spend it in a shop.

The server store, and emeralds

The Market stall is still here, still sells at fixed prices, and still takes emeralds - it came before the new money and has not changed. So two currencies are in play: dollars between players, emeralds at the Market and with villagers. Treat the Market as the price floor: if a player shop asks more than the Market for the same thing, you are being had.

Admin shops

An admin shop is a shop with the server behind it rather than a player. It never runs out of stock and never runs out of money — and nothing it sells comes from a chest, so nothing has to be restocked. Only an operator or someone in creative mode can make one.

They are for fixed prices that should always be available: a starter shop at spawn, a sink for something people have too much of, a reference price so nobody gets fleeced.

  1. Make an ordinary shop first.

    Chest, sign placed by you, then /shop sell 5 or /shop buy 5 exactly as above. /adminshop does not write the sign — it only changes who owns it, so the shop has to work before you mark it.

  2. Look at the sign and run /adminshop.

    That's it. The shop now belongs to the server.

  3. Or name the sign by position: /adminshop at <x> <y> <z>

    Useful when you can't get line of sight on it, or when you are marking several.

  4. Changed your mind: /adminshop off

    Hands the shop back to you, as its ordinary owner. Same two ways of naming the sign.

Sign saysWhat the admin shop doesThe chest
[buy]Sells to anyone, for ever. Stock never runs down.Stays empty. Nothing is taken out of it.
[sell]Buys from anyone, for ever. Never runs out of money.Stays empty. Nothing is put into it.

The chest is still needed, and it still stays empty. An admin shop reads nothing out of the chest and writes nothing into it, so there is no point stocking one — and no harm in the chest being there. The money the customer pays simply stops existing, and the money an admin shop pays out simply appears.

The customer side is unchanged: one right-click buys or sells one item, they are told the price and their new balance, and they are still refused if they can't afford it, don't have the item, or have a full inventory.

If /adminshop doesn't autocomplete after you switch to creative, rejoin. The game sends your client the list of commands you're allowed when your operator status changes, but not when your gamemode does. The command still works if you type it out in full; rejoining just makes the tab-completion catch up.

Mining

This pack adds a lot of ores on top of the vanilla ones. You don't need to memorise them — two tools tell you everything as you go.

Turn these on first

Vein mining

Hold ~ and break a block. That is the tilde/backtick key immediately left of 1, on the row above Tab. Everything connected to that block breaks with it.

This is FTB Ultimine, and it is the single biggest quality-of-life feature on the server:

  • Whole trees — one swing at the trunk and the entire tree comes down, leaves and all. No jumping, no leftover floating logs.
  • Whole ore veins — hit one block of a vein and take all of it, including modded ores.
  • Tunnels, fast — hold it while digging and you carve corridors far quicker than block by block.

You will see the affected blocks highlight before you break anything, so you always know what you are about to take. It handles up to 64 blocks at once here, and eats hunger in proportion — bring food if you are felling a jungle.

If ~ does nothing, it is almost certainly unbound rather than broken: this pack ships KeybindsPurger. Open Controls, find Activate Ultimining under the FTB Ultimine category, and set it to whatever you like.

The block tooltip

Look at any block and Jade puts a small panel on screen telling you what it is, which mod it came from, and often what tool it needs. When you hit an unfamiliar ore three hundred blocks down, this is what tells you whether it's worth mining.

Roughly how ores tier

You still start with stone, iron and diamond in the usual places at the usual depths. Beyond that the pack's ores sort loosely into:

  • Common metals — copper, tin, lead, silver, nickel, zinc and friends, throughout the overworld at ordinary depths. These feed nearly every machine recipe, so gather far more than feels necessary.
  • Deep and dimensional ores — the genuinely rare materials, at extreme depth or in other dimensions, usually behind a tool tier you have to build up to. Don't hunt these early; you'll just die a long way from home.
  • Grown resources — Mystical Agriculture lets you farm most materials as crops once you're established. Slower to set up, far faster afterwards, and the usual answer to "I need ten thousand of these."

Check before you dig. Press U on an ore or ingot to see everything it feeds into. Faster than reading six wikis.

Take a backpack

You will fill your inventory faster than you expect. A Sophisticated Backpack early on is worth more than better armour — it upgrades later to pick up, sort and even smelt what you mine.

Mine inside a claim if you're leaving machinery down there. Quarries, drills and anything automated only keep running in a force-loaded chunk, and unclaimed tunnels aren't protected from anything.

Sorting chests

The first real problem in a pack this size isn't finding things — it's that an hour of mining and looting leaves you with eleven chests of unsorted rubbish. SortCraft fixes that with signs. No redstone, no hoppers, no machines, and you can build it on your first day with wood and a few chests.

This is a day-one tool, not an endgame one. Once you have an AE2 or Refined Storage network running, that replaces it completely. SortCraft is what gets you through the many hours before then.

Build it in three steps

  1. Put chests down and label each one with a sign.

    Place a chest, then put a wall sign on the side of it, and write a category name in square brackets on any line: [ores], [food], [wood].

    It has to be a wall sign — one stuck to the side of the block. A standing sign on top of the chest does nothing, and neither does a hanging sign: SortCraft finds the chest by looking at what the wall sign is attached to, and those two aren't attached to anything. This is the single most common reason a chest never fills.

    All four lines are read, front and back, so the other lines are yours to label with.

  2. Put down one more chest and label it [input].

    This is the bucket you dump everything into when you get home. It doesn't need to be next to the others — see the range note below.

  3. Dump your loot in, then right-click the [input] sign.

    Everything that matches a category flies to the right chest. Anything with no matching category stays in the input chest, so nothing ever goes missing.

    Shift + right-click the same sign to preview instead — it tells you what would go where without moving anything. Worth doing the first time so you can see your layout working.

How close do the chests need to be?

They don't need to touch. Nothing has to be adjacent to anything else — not the destination chests to the input chest, and not the destination chests to each other. Everything just has to be within 16 blocks of the input chest, which is a generous room.

The only thing that must physically touch is each sign and its own chest. Beyond that, put the chests wherever they look good: two walls of a storage room, both floors of a tower, scattered around a basement. The input chest can sit by your front door with everything else a corridor away.

One sign per chest, one chest per category. Double chests count as a single chest, so a double chest is the easy way to give a busy category more room.

What counts as a chest

Anything that holds items, not just wooden chests. Barrels work, Sophisticated Storage barrels and chests work, and Functional Storage drawers work — and drawers are worth a section of their own, below.

Drawers, and one sign for a whole column

A sign labels the container it is stuck to and every storage block directly underneath it. SortCraft walks straight down from the signed container and keeps going until it hits something that isn't storage, or a container that carries a sign of its own.

That is what makes drawers work properly. Put a Functional Storage drawer down, sign it [ingots], then stack five more drawers below it — no more signs — and that one category now has six drawers' worth of room. A drawer holds one item type per slot in enormous quantity, so this is far and away the best home for the bulk categories: [ingots], [stone], [wood], [crops].

  1. Build the column downward, not sideways.

    The sign goes on the top container. Anything beside it is a separate chest that needs its own sign.

  2. Seed the drawers before the first big sort, or lock them.

    An empty drawer slot takes whatever arrives first and then only accepts that one item. SortCraft asks each slot whether it will take an item and never forces a wrong one in — but it does mean the first sort decides what each slot becomes. If you want a particular layout, put one of each item in by hand first, and a lock upgrade keeps it that way even when the drawer empties.

  3. If it's full, nothing is lost.

    Items with nowhere to go stay in the input chest. They are never dropped or destroyed.

Barrels and Sophisticated Storage chests stack the same way, so you can mix them in a column.

Shulker boxes in the input

Drop a shulker box or a bundle into the input chest and SortCraft empties it and sorts what was inside, which makes a shulker box the natural way to carry a mining trip home in one slot.

The exception is a box that holds ten or more stacks of the same thing. That reads as deliberate storage rather than luggage, so the box is filed whole, as an item, instead of being unpacked.

Start with six chests

There are 57 categories, plus one for every mod in the pack, but you do not need to care about that yet. Sign six chests with these and you have covered nearly everything the game will throw at you:

  • [ores]Ore, raw metal, ingots, nuggets, gems, dust, coal and metal blocks
  • [food]Anything edible, plus drinks
  • [gear]Every weapon, tool, shield and piece of armour
  • [bulk]Stone, dirt, sand, wood, glass, stairs, slabs — building material
  • [farming]Seeds, saplings, crops, bonemeal
  • [loot]Mob drops, discs, sherds, heads and trinkets

Then split them when a chest fills up

This is the part worth understanding, because it means you never have to redo your storage room. Categories are arranged in tiers, and an item takes the most specific chest that exists. If you have not built that chest, it rolls up to the general one instead.

So a diamond looks for [gems], and if there is no such chest it settles for [ores]. The day [ores] gets too full, you put down a chest, write [gems] on it, and gems start going there by themselves. Nothing else changes.

General chestSplit it into any of these
[ores][raw_ore] [ingots] [nuggets] [gems] [dusts] [plates] [blocks] [coal] — or [metals] for the worked ones together
[food][meat] [fish] [fruit] [vegetables] [drinks] — or [meat_raw] and [meat_cooked] apart
[gear][weapons] [tools] [armor] — then [swords] [bows] [pickaxes] [axes] [shovels] [hoes] [shields] [utility_tools] [helmets] [chestplates] [leggings] [boots]
[bulk][stone] [wood] [earth] [glass] [shapes] [decoration] [containers] — or [building] for all the worked blocks
[farming][seeds] [saplings] [crops] [fertiliser]
[loot][mob_drops] [trophies] — and [tech] for redstone parts

[wood] and [stone] go by what a thing is made of. Anything made entirely of wood lands in [wood] — planks and logs, but also doors, fences, gates, trapdoors, buttons, pressure plates, stairs, slabs, signs, boats, bowls, ladders and sticks. Anything made entirely of stone or cobblestone lands in [stone] the same way — walls, stone stairs and slabs, furnaces. Both beat [shapes].

What a thing is FOR still beats what it is made of. A wooden pickaxe is still [pickaxes], a chest and a barrel are still [containers], and charcoal is still [coal] even though it is smelted from logs and so counts as wood quite literally. Mixed things belong to neither: a lever is cobblestone and a stick, so it stays where it was.

If you have not built a [wood] or [stone] chest, none of this changes anything — those items fall through to [shapes] and [bulk] exactly as before.

Four that sort by what happened to an item

These are checked before everything above, so they win over the ordinary category for that item type. Each one is inert until you build its chest.

  • [named]Anything you renamed in an anvil. The reason to bother: your favourite pickaxe stops vanishing into a chest with forty others. Name it once and it always comes home here
  • [damaged]Tools, weapons and armour at 25% durability or less — the repair pile
  • [enchanted]Any enchanted gear, kept away from the plain stuff
  • [enchanted_books]Exactly what it says

A chest for exactly one item

Every single item in the pack is its own category, named by its full id — the mod's name, a colon, then the item. Sign a chest [minecraft:lead] and it takes leads and nothing else.

It has to be the full id. [lead] on its own is not a category and deliberately never will be. Short names go wrong the moment two mods both add something with the same one, and every short word spent this way is a word that could never be given to a proper category later.

These beat everything. A chest signed [minecraft:diamond_pickaxe] takes every diamond pickaxe, even a renamed, enchanted or nearly-broken one, ahead of [named], [damaged] and [pickaxes]. That is the point of them — one thing you care about, always in the same place — but it does mean an item chest quietly outranks the rest of your sorting room for that one item.

Don't type them by hand. A sign line holds about fifteen characters, nowhere near enough for most modded ids. Hold the item, look at the sign, and run /signitem — it writes the id for you, split across the sign's lines so it still sits inside the sign. A name split that way sorts exactly as if it were on one line.

Not sure what something is called? /sort category <item> lists every chest name that would take it, and F3 + H turns on tooltips that show an item's id.

A chest for one mod

Any mod's own name works as a category. Sign a chest [horsegenetics] and everything from Procedural Horse Coats lands in it; [ae2], [mekanism], [occultism], [railcraft] and 182 others all work the same way.

The name to write is the mod's id, which is the part before the colon in an item's id rather than its pretty name. Press F3 + H once to turn on advanced tooltips and every item shows you its id; /sort category <item> will also tell you, and it names the mod chest along with the normal one.

Mod chests are checked last, just ahead of [misc], so everything above beats them. If you have an [ingots] chest and a [mekanism] chest, Mekanism's ingots still go to [ingots]. A mod chest is for the things a mod adds that fit nowhere else — machine parts, ritual components, its own oddities — not a way to pull a whole mod out of your sorting room.

[misc] catches everything else. Build that chest and nothing is ever left behind — but you also stop noticing what has no proper home. Leaving it out is the better default: unmatched items stay in the input chest where you can see them, and you can say so in chat.

Commands worth knowing

  • /sort previewShows what would move where, without moving it. Same as shift + right-clicking the input sign
  • /sort category <item>Tells you which category an item belongs to, so you know which chest to build
  • /sort whereis <item>Finds where something is already stored and highlights those chests with a glowing outline you can see through walls
  • /sort inputSorts the nearest input chest, if reaching the sign is awkward
  • /signitemHold an item, look at a sign, run this and the sign labels itself for that item. Saves typing a long id by hand. /signitem add writes into the sign's empty lines instead of clearing it
  • /sort helpThe full list

When it doesn't work

  • Nothing moved. The sign text has to match a category name exactly, brackets included — though it can be on any line, front or back. If the whole chest is ignored, check the sign is a wall sign on the side and not a standing sign on top.
  • Some items stayed behind. That's correct behaviour — they don't match any category yet. Run /sort category on one and say so in chat if it looks like it should have a home.
  • One chest never fills. Check that its sign is actually attached to that chest and not to the block beside it.
  • A chest filled up. Items that don't fit stay in the input. Make it a double chest, or point that category at a drawer.

Getting around

The world is large and generated by four terrain mods at once — Terralith, Tectonic and Regions Unexplored in the Overworld, Nullscape in the End — so it's genuinely worth exploring. Set up fast travel early so exploring isn't a one-way trip.

Waystones

Waystones are the fast-travel network. Some generate naturally in villages and structures; you can also craft and place your own.

  1. Find or place one and right-click it to activate it.

    It's on your list permanently from then on.

  2. Right-click any other waystone to travel.

    Pick a destination from everything you've discovered.

  3. Put one at home first.

    Then activate every waystone you stumble across. The network is only as useful as the number of pins in it.

Paths make you faster

Walk on a path block and you move noticeably quicker — about 40% faster, and it applies the moment you step on. It works for horses too, and a horse pulling a cart drags the cart along at the same speed, so a proper road is the cheapest travel upgrade in the pack.

  1. Join up the places you actually walk between.

    House to mine, base to farm, spawn to your build. Short hops you make twenty times a day are worth more than one long scenic highway.

  2. Real paths count. Bare ground does not.

    The vanilla dirt path — the one you scrape out with a shovel — works, and so does every one of the 316 blocks in Macaw's Paths: stone paths, paving, flagstone, cobble walkways, crystal floors, and the slabs and stairs of all of them. Same speed from every one, so build whatever looks right.

    Plain dirt and coarse dirt give you nothing, and burying coarse dirt under the surface to make a hidden fast lane does nothing either — that was switched off on 24 September, because natural coarse dirt underground was handing out the boost at random in badlands and taiga.

  3. Two blocks wide is plenty.

    Enough that you stay on it without steering. Widen it later if you are riding with someone.

Mobs get the speed boost too. Anything standing on your path moves faster, including whatever is chasing you. Light your roads properly — an unlit path is a fast lane for creepers as much as for you.

Horses

The horses here are not vanilla horses. Procedural Horse Coats gives every one of them a real genome — coat, build, temperament and stats, all of it inherited by its foals. It's written by the person running this server and it updates most days, so the mod's own wiki is the source of truth, not this page. This tab is just enough to get you started.

The controls

  • E, from the saddleThat horse's own menu — genes, family, gear. Press it again to close
  • HThe horse browser: every horse you own
  • RAttach or detach a cart from the horse you're riding

The saddle menu follows whatever your Inventory key is, so if you've moved it off E, use the key you moved it to. Donkeys and mules still open their ordinary inventory. If one of these does nothing at all it's more likely unbound than broken — KeybindsPurger strips conflicting defaults, so check Options → Controls first.

Keeping one alive

Two things are worth knowing before you own a horse, because neither is vanilla:

  1. A hurt horse needs water nearby and a full stomach to heal.

    Water within three blocks, and not starving. Vanilla's free trickle of regeneration is switched off for horses, so a hungry horse stays hurt until you feed it. Leave water and something to graze in the pen and it sorts itself out.

  2. They graze, so fence your farm.

    A horse eats crops whole and turns grass to dirt the way a sheep does. It won't reach through a fence, but an open gate is an open invitation.

A horse is hard to lose now. Nothing kills one in a single blow — a killing hit leaves it on half a heart with a few seconds of immunity instead. Below a fifth of its health it stops answering the reins and bolts, carrying you out rather than throwing you. Let it run.

Your own horses also talk to you in chat: what hurt one and what to do about it, who lost one and to what, and why a mare wasn't covered.

Building and decorating

There's a deep set of decoration mods here — Macaw's furniture, windows, doors, roofs, fences, paths, bridges, stairs and lights, plus FramedBlocks, which take on the appearance of anything else. If you enjoy the building side, browse these in the recipe viewer; there is far more available than the vanilla palette suggests.

The server tidies up every hour

On the hour, every hour, two things are removed. A warning goes out in chat two minutes before and again at thirty seconds, so there is always time to react.

  • Items lying on the ground, in every dimension. Death drops are safe — dying puts your inventory into a grave block, not loose items on the floor — but anything you deliberately left lying about to deal with later does go. Put it in a chest.
  • Zombies, skeletons and creepers more than 128 blocks from every player online. That is further than you can see, so you will never watch one vanish. Husks, drowned, strays, bogged and wither skeletons go too; zombie villagers never do, so a cure in progress is safe, and neither does anything you have name-tagged.

This is a performance measure rather than a rule. You will also see a one-line [Perf] summary in chat at five past the hour - TPS, tick time, entity and horse counts for the hour just gone - so it is obvious when the server is struggling and when it is fine. Thousands of forgotten items and mobs ticking away in chunks nobody is standing in is the main thing that makes the server stutter. One thing to know if you build a mob farm: a chamber that holds mobs alive will empty itself once you walk away from it, while a farm that kills them into a chest is fine.

Getting unstuck

  • Can't find a recipe? Search the item in the recipe viewer. If it has none it probably comes from a quest, a dungeon or a mob.
  • Machine not working? Nine times out of ten it's power, or an input on the wrong face. Look at the block to see its status panel.
  • Something feels broken? Say so in chat rather than working around it. Usually it's a known quirk with a one-line fix.

Troubleshooting

Nearly every failure here is a version mismatch wearing a disguise. The error text almost never names the real cause — so find your message below rather than trusting what it blames.

Check these four first. Most problems on this page are one of them being wrong. They are not interchangeable and "newer" is not always safer.

The launcher won't even open

"invalid JVM argument(s) ... --add-modules=javafx.controls,javafx.fxml"

  • This is not Minecraft, and not the pack
    • The error names org.jackhuang.hmcl.Main — that's HMCL (Hello Minecraft! Launcher) failing to start.
    • The game never launches, so the pack is not involved. Redownloading the pack cannot fix this, and neither can any change to it.
  • What it means
    • HMCL is a JavaFX application. Those repeated --add-modules=javafx... lines are it trying several ways to find JavaFX, failing every time, and then failing to load its own main class.
    • A plain JDK has no JavaFX in it. It was unbundled at Java 11, and the common builds — Temurin/Adoptium, Microsoft, Corretto — do not ship it.
  • How to fix it — either one works
    • Run HMCL's Windows .exe, not the .jar. The .exe brings a runtime with it. Double-clicking the .jar hands it to whatever java is on your PATH, which is exactly the JDK that has no JavaFX.
    • Or install a JDK that includes JavaFX and point HMCL at that: BellSoft Liberica JDK — the Full package — or Azul Zulu JDK FX.
  • The launcher's Java and the game's Java are two different settings
    • Minecraft 26.1.2 wants Java 25. HMCL itself wants a JavaFX-capable Java.
    • Setting one does not set the other, and installing Java 25 for the game is what leaves HMCL unable to start.
  • If you use HMCL, turn version isolation on
    • By default it shares one .minecraft across every version you've installed, so another version's mods and libraries mix into this one.
    • That is a common route into the LWJGL error below.

It crashes while loading

"NoSuchMethodError ... Callback$Descriptor"

  • What you'll see — a fatal error during mod loading, roughly:
    • java.lang.InternalError: java.lang.NoSuchMethodError: 'void org.lwjgl.system.Callback$Descriptor.<init>(java.lang.invoke.MethodHandles$Lookup, org.lwjgl.system.libffi.FFICIF)'
  • What it actually means
    • Your instance is running LWJGL 3.3.3. Minecraft 26.1.2 needs 3.4.1.
    • In 3.3.3 that class does not exist at all, so the first mod to touch it dies — usually Sodium.
    • Nothing is wrong with the pack, and nothing is wrong with Sodium. Deleting mods will not fix it.
  • Why it happens — almost always the first of these
    • You installed NeoForge for a different Minecraft version. NeoForge builds are tied to one Minecraft version, so the wrong one quietly launches that version instead — and 1.21.8 and the 25w3x snapshots all use LWJGL 3.3.3. The build you want starts 26.1.2.; anything else is the wrong game. This is the one that has actually bitten someone here.
    • Or the instance was copied from an older Minecraft, and the old library setting came along with the copy.
    • Or your launcher lets you pin an LWJGL version, and it is pinned low.
  • How to fix it
    • Prism or MultiMC — Edit Instance → Version. "LWJGL 3" is its own line: set it to 3.4.1, or remove the override so it follows the game.
    • Official launcher or CurseForge — build a fresh 26.1.2 instance and install NeoForge into that. Do not copy or upgrade an older one. Failing that, make the launcher re-verify its files so 3.4.1 downloads.
    • To confirm before you start — search your launch log for lwjgl-3.3.3. If it's on the classpath, this is your problem.
  • Do not "fix" this by changing Java.
    • Java 25 is correct here — 26.1.2 asks for it by name. Downgrading Java will only break something else.

"... requires neoforge 26.1.2.109 or above"

  • It names a mod, but the mod is fine.
    • Whichever mod is named is simply the first one to check. Your NeoForge build is too old.
    • This is the single most misleading message you can hit here, because it reads like a broken download.
  • Fix
    • Install 26.1.2.109 or newer. .106 is not close enough.

It crashes naming lambdynamiclights

  • Known-shaky on some setups
    • It packages its libraries in a layout NeoForge doesn't always accept.
    • Delete that one jar from mods. Nothing else depends on it and the rest of the pack is unaffected.

It runs out of memory, or stutters then dies

  • The default 2 GB will not load this pack
    • Edit your installation → More options → JVM arguments.
    • Change -Xmx2G to -Xmx8G, or -Xmx6G if the machine only has 8 GB total. Leave the rest of the line alone.

It won't connect

"The server sent registries with unknown keys"

  • A long list of item names, and none of them are the problem
    • Your config or kubejs folder is missing or incomplete.
    • Several mods build their item lists from those files, so a client without them genuinely knows about different items than the server does.
  • Fix
    • Copy all four folders across — mods, config, kubejs, resourcepacks — then relaunch.

A mod-list mismatch, or the server never appears

  • Count your jars first
    • There should be 370 files in <game directory>/mods/.
    • Check you don't have mods/mods/ — unzipping one level too deep is the classic mistake.
    • Two versions of the same mod will also stop the game loading. One jar per mod.
  • If the server isn't in the list at all
    • Tailscale must say Connected. If it doesn't, nothing else matters.
    • The download page is the quickest test: it only resolves on the tailnet, so if it loads, you're on.

It runs, but something looks wrong

  • Shelf-Shrooms warns it's for an older version
    • Expected. Confirm past it — the pack is optional and cosmetic either way.
  • A keybind does nothing
    • KeybindsPurger may have stripped it. Re-bind it in Controls rather than assuming the mod is broken.
  • The first launch looks frozen
    • 370 mods take several minutes the first time, and it will appear stuck more than once. Every launch after is much quicker.

Still stuck? Send Isabel the log, not a description — <game directory>/logs/latest.log. The real cause is usually a hundred lines above the part that looks like the error.
